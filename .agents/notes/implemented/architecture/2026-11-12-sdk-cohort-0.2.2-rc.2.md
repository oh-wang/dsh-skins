# Agent Note: SDK cohort 0.2.2-rc.2

Status: implemented

## Problem

The repository tracked the 0.2.2-rc.1 cohort while the host moved to 0.2.2-rc.2 (dsh-web 6d343f14e and 971cc3e1f). Advancing the manifests alone would not have been enough: `pnpm-workspace.yaml` carries a 321-entry `minimumReleaseAgeExclude` ledger naming every `@deepseek-ai/*` package at 0.2.2-rc.1, so an install would keep resolving the old cohort from that ledger and the repository would only claim rc.2 in its declarations.

## Decision

All nine SDK development dependencies, the `@deepseek-ai/dsh` peer and both host floors move to rc.2: the exact pins become `0.2.2-rc.2`, and `dsh.engines.dsh` and the peer become `>=0.2.2-rc.2`. `@deepseek-ai/cordis` (`^4.1.0`) and `@deepseek-ai/schemastery` (`^3.19.0`) are unchanged because rc.2 does not move them. The release-age ledger moves with the cohort, pnpm appends the fourteen transitives the new resolution reaches, and the lockfile is regenerated so the tree resolves rc.2.

No source adaptation was required. rc.2 withdraws the internal subpath exports such as `@deepseek-ai/dsh-subagent/internal` and reshapes `startActivation`, `drainChildren` and `drainDescendants`; this repository imports none of them. The surfaces it does consume - `cordis`, `schemastery`, `dsh-host-webserver`, `dsh-client-ui-slots`, `-settings`, `-theme`, `-renderer`, `dsh-api-remotes`, `dsh-api-workspace-controller`, `dsh-client-locale` and `dsh-settings` - keep every shape the sources use, so `lib/` rebuilds byte-identical.

Two frozen contracts were re-verified rather than assumed. All five `dsh.client.inject` packages still publish a `./client` entry under rc.2. The vendored `contracts/official-tokens-v1.json` was compared against the rc.2 theme library: rc.2 retires no token the snapshot records, so the skin center cannot emit a withdrawn custom property, and its 335 entries stay a valid subset of the larger rc.2 surface.

The README badges on both sides state the host floor, so they move to `>=0.2.2-rc.2` and `README.i18n.yaml` re-records the pairing hashes.

## Alternatives considered

**Regenerate `contracts/official-tokens-v1.json` from the rc.2 packages.** Rejected for this change: the artifact is marked GENERATED and its generator, `scripts/official-tokens-snapshot.mjs`, is no longer in the tree. Hand-writing 36 additional entries without that generator would invent surface the repository has never verified against the frontend dist, which is the second half of the snapshot's stated source.

**Leave the release-age ledger on rc.1.** Rejected: the ledger is what actually decides the resolved cohort, so leaving it would have produced a repository that declares rc.2 and builds against rc.1.

**Raise the package version or publish.** Rejected: the version stays 0.4.17 and release coordination is held outside this change.

## Consequences

`pnpm typecheck`, `pnpm test` (73 files, 822 tests), `pnpm build`, the committed-`lib` diff check, `pnpm skin-hooks:check`, `pnpm skin-center:check` and `node --test scripts/*.test.mjs` (51 tests) all pass against the rc.2 tree. A host at rc.1 can no longer install this package, which is the intended effect of the floor.

Locally, a bare `pnpm install` exits non-zero with `ERR_PNPM_IGNORED_BUILDS` for `@deepseek-ai/dsh-subprocess-local`, because `allowBuilds` still holds the placeholder pnpm wrote instead of a decision. This predates the cohort move - it reproduces at HEAD against rc.1 - and does not affect CI, which installs with `--ignore-scripts`. It is left alone here so the cohort bump stays one reviewable change.
