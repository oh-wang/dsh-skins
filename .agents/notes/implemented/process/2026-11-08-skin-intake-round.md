# Agent Note: 2026-11-08 皮肤收录轮

Status: implemented

## Problem

2026-11-08 的皮肤收录轮需要对仓库当前开放的 7 个 PR（#77、#85、#93、#97、#99、#105、#106）按来源与版权闸门、版本递增规则、目录契约、最新提交下的用户可见截图证据以及视觉可读性逐项核验，裁定已收录皮肤的对比度修复 PR #105 与新皮肤 PR #106 是否满足合入 `main` 与商店上架条件，并确认其余开放 PR 的本轮状态。

## Decision

- **#105（`remiel-starlit` 对比度修复）：退回（三项）。** 改动方向合理（`static-neutral` 梯度保持深色、`neutral-00` 保持白色、补 `alias-link` 与 `toast-label`），亮暗两张截图里卡片文字均可读；但 `skin.json` 的 `version` 仍为 `0.1.0`、与 `main` 相同，商店不会把它当成更新，用户收不到这次修复——这是阻塞项。另两项：两张截图右上角有黑底「Z·Z·Z」徽标（约 x1443-1555、y40-188），需说明是否为壁纸自带水印并写入 `NOTICE` 或换素材；暗态截图里角色上下颠倒（头部在下方，约 x500-900、y420-760），需确认是否为有意的构图。
- **#106（`Whale Desk` 新皮肤）：阻塞不合并。** 来源闸门不满足：作者自己的 `NOTICE` 与 `ARTWORK.json` 写明角色再分发授权「尚未独立核实 / Character clearance is outstanding」，PR 清单里「第三方角色再分发范围已被接受」一栏未勾，也缺「版权责任由贡献者承担」的措辞；角色是以他人角色为参考生成的二创，需要取得原作者许可或改为原创角色。证据闸门有瑕疵：PR 正文里的 `native-light` / `native-dark` 来自首个提交 `37fc39da`，而 `skin.css` 与 `patches.css` 在其后的 `07e1a6ec`、`721e478d` 还改过；较新的暗态截图 `chat-dark-after-restart` 右侧有第三方桌宠气泡、真人头像小窗与白色工具条，气泡压到正文区边缘。美学为「需修改」：暗态遮罩过重导致插画发灰、聊天页背景几乎不可见；亮态聊天页「已完成，用时 3 秒」一行被鲸尾压住部分文字。另指出 `sourceUrl` 指向作者 fork 的 `feat/whale-desk` 分支、合并后会失效，以及 `DESK-OVERRIDES.css`、`TESTING.md`、`validation/` 等偏离既有皮肤目录约定的文件。
- **#77、#85、#93、#97、#99**：维持既有状态，作者本轮未再更新。

## Alternatives considered

- **以美学与截图瑕疵作为 #106 的首要退回理由并引导作者优先调样式。** 否决：来源与授权闸门是上架的前置硬约束；作者已在 `NOTICE` 与 `ARTWORK.json` 中自述第三方角色再分发授权尚未独立核实，在该项未解决前，即便暗态遮罩与截图污染全部修妥也无法合入分发，将视觉问题排在首位会误导作者把精力投入在次要返工上。
- **鉴于 #105 的 CSS 对比度改动本身有效，直接合入而不要求递增 `skin.json` 版本号。** 否决：商店客户端依赖 `skin.json` 的 `version` 字段识别远端资产包更新，维持 `0.1.0` 会使已安装该皮肤的用户无法收到修复；同类问题在 2026-11-07 的 #104 审查中已按「既有皮肤修复必须递增版本」执行，跨轮次应当保持一致的准入判定。

## Consequences

- 本轮 `skins` 无合并，`main` 未变，因此没有对应的市场钉版移动（其余仓的钉版在本轮已与上游一致）。
- 两个退回项都属于「可修但要重新提交」：#105 只需递增版本并说明徽标与构图；#106 需要先解决角色许可，再重拍最新代码下的干净截图并调暗态遮罩。
- 同一问题在 #104 与 #105 上连续出现（既有皮肤修复不递增 `skin.json` 版本），说明商店更新语义尚未被贡献者普遍理解，下一轮可在审查模板里前置这一条。
