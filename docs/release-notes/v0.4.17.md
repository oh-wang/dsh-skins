皮肤中心发布 0.4.17，与全家桶 0.4.17 同版本发布。皮肤目录从 65 套增至 66 套，新增浅色专用的水彩皮肤 `whale-watercolour`；`remiel-starlit` 修回了明暗两个模式下都被压坏的正文对比度，并把皮肤版本抬到 0.1.1 让商店能把它判成一次更新。包名、安装方式、语义属性名与 npm `files` 白名单一个不动。

> **兼容性**：本版本没有破坏性变更，也没有需要手工迁移的改动：包名 `@linxin666/dsh-client-ui-skin-center`；安装方式（`dsh plugin --profile <name> add` 与 `$DSH_HOME/skins/<id>` 目录布局）；npm `files` 白名单仍只内置 `blue-fantasy`，新皮肤是市场内容、按需装进 `$DSH_HOME/skins/<id>/`；`dsh.engines.dsh` 与 `@deepseek-ai/dsh` 对等依赖下限仍是 `>=0.2.2-rc.1`（本仓本版未随主仓抬到 rc.2）；v2 活跃状态文档的持久化文件名与键名；`data-dsh-skin`、`data-dsh-part` 等语义属性名；线协议字段——全部未改名。新皮肤是纯 CSS 资产（`hooks` 为空，没有任何东西会执行），不引入新的运行时契约；`remiel-starlit` 的修复只改它自己的令牌值与 manifest 版本，Reviewed Skin Hooks 记录不变。

### 新功能

- 新增 `whale-watercolour` 皮肤（188c0af，#77，skin 1.0.2，order 54，主色 `#1B5D9A`）：一张水彩插画上的浅色专用皮肤——蓝发少女、发间白色小花与白玫瑰、银色菱形吊坠珠链、翡翠绿的眼，机壳不是画在画上，而是一层半透明奶白薄纱，画从纸背透出来。色板每一支都从那张画里量出而不是凭眼睛挑：奶白 `#FAF9F5` 取自画面里占 34.6% 的那片，墨蓝 `#0D2045` 取自最暗 0.2% 的均值再压深一档，蔚蓝 `#1B5D9A` 取自最饱和 2% 的均值再压深一档，翡翠 `#186654` 由实测眼部绿同色相压深；冰蓝 `#B0C8D8` 只做装饰线，因为它在任何一层薄纱上都只有 1.65–2.18:1，永远不能当交互边界（3:1），那里改用蔚蓝与翡翠。五档薄纱 alpha 在 sRGB（gamma 编码）空间反解而不是线性光：`rgba(250,249,245,0.678)` 压在 `rgb(38,60,100)` 上落到 `rgb(182,188,198)`，sRGB 模型逐通道命中，线性光模型偏 29
- 薄纱厚度按逐格纸面证据重新求解，而不是按「最暗 1%」（那个口径把文字本身与头发暗块读成纸面）：14x48 px 单元格取 p75 亮度作纸面，再经 `under = (P - a*VEIL)/(1-a)` 折回，于是每档都能逐样本复合验证。五个旋钮一次性前移——侧边栏/页眉 0.82 → 0.56、顶栏 0.78 → 0.56、输入卡 0.66 → 0.52、对话纸面 0.58 → 0.46 → 0.38、菜单 0.95 → 0.80，画面保留率从 18% / 22% / 34% / 42% / 5% 提升到 44% / 44% / 48% / 更高 / 20%（纸面在第三笔里单独推到 0.38，逐格测得的底线是 0.34，最差 5% 文字格仍有 7.2:1）；文字颜色一个没改，最差 5% 的文字格仍测得 9.14 / 8.18 / 8.16 / 10.67 对 7.0 的地板，次级与状态档全部 5.6:1 以上。菜单没有活壳样本（必须打开才能测），因此保留 0.15 的余量
- 暗色半边被钉在浅色半边，而不是只声明「相同」：在运行中的壳上，仍有四处会生成第二套值——5 个引擎 `--sk-*` 令牌、22 个这套皮肤从未重映射的壳令牌（deep-diving / shimmer、菜单图标、链接、文件 diff 与代码 diff、菜单与回合触发面、onboarding，以及 9 个 shiki 语法色）、两条根本不是令牌的暗色规则（工具图标块填充、右栏引导字形颜色），以及 `color-scheme`（它把所有未加样式的原生控件刷白）。现在它们全部解析到浅色值：**553 个壳自定义属性在两个主题之间 0 个不同、8 个真实场景 0 处计算样式差异**，官方市场试穿页上亮暗两版渲染**逐像素相同（1,680,000 个像素 0 个不同）**。浅色侧未被改动：36 个钉住的取值仍解析到与改动前完全一致的值

### 修复

- `remiel-starlit` 明暗两侧可读性修复（d53865e，#105）：暗色分支把整条 `--dsw-static-neutral-*` 阶梯反转成浅色值，于是官方壳里所有「白字压深底」的假设同时失效——交付、计划、日程、forge 与变更文件卡从 `--dsw-static-neutral-850` 取板底色，而 `--dsw-alias-label-primary` 仍是浅色，白字压在 `#ded7db` 上只剩 **1.28:1**。那条阶梯在官方主题里是与主题无关的绝对调色板，只有 `--dsw-alias-*` 会随主题翻转，反转它等于把任何静态底面的表面踢出主题系统，没有任何东西能兜住。改法：暗色分支保持阶梯为深色而不镜像成浅色值；`--dsw-static-neutral-00` 保持白色，因为壳用它当白色叠加层（图标底 50%、高程光、侧栏高亮闪），翻转会把每一处「提亮」变成「压暗」
- 同一笔里抬高浅色半透明表面的 alpha（`bg-base` 0.42 → 0.62、`sidebar-fill` 0.60 → 0.74，以及 layer-1..3、气泡与输入卡），让三级与说明文字在平静底图的较暗区域仍能活下来；`label-tertiary` / `caption` / `dimmed` 一并加深以在这些表面上达到 4.5:1；另外补上两个皮肤从未重映射、因而回落到官方色板的令牌——`--dsw-alias-link` 此前解析成褪色粉、只有 1.97:1（每一处 Markdown 链接与 WebBlock 引用都受影响），`--dsw-alias-toast-label` 则在皮肤自己的 toast 面上仍用壳的取值。重建后实测：暗色卡片 1.28:1 → 11.07:1，浅色卡片 10.82:1，注记文字 7.44:1，**全部 192 种表面/文字/主题/底图组合通过 WCAG AA 4.5:1**
- 皮肤版本 0.1.0 → 0.1.1，并写明随发布的原图上带官方水印：商店比较的是 manifest 版本，版本不动这次修复就看不见、用户永远收不到；`NOTICE` 声明资产按原发布形态携带《绝区零》官方 logo 水印，该标记归 miHoYo 且是素材的一部分，皮肤既不裁切也不遮盖它，从而保住必需的版权标记；中英 README 各补一节 0.1.1 变更说明，证据截图按重建后的样式表重出

### 其他改动

- 记录两轮皮肤收录：区间内的两笔 `docs(notes)` 提交把 2026-11-08 与 2026-11-09 两轮收录的评审结论与取舍写进 `.agents/notes/implemented/process/`，不改皮肤资产、契约或运行时代码

- 目录规模：仓库内目录皮肤 66 套，npm 白名单仍只内置 `blue-fantasy`，其余全部作为市场内容按需安装；新皮肤不引入新的令牌契约，共享样式表与 Reviewed Skin Hooks 记录未变

The skin center publishes 0.4.17, on the same version as the dsh-web family's 0.4.17. The catalog grows from 65 skins to 66 with the light-only watercolour skin `whale-watercolour`, and `remiel-starlit` gets its read contrast back in both modes, with the skin version moving to 0.1.1 so the store can see the repair as an update. The package name, the install path, the semantic attribute names and the npm `files` whitelist do not move.

> **Compatibility**: this release is not a breaking change and nothing has to be migrated by hand: the package name `@linxin666/dsh-client-ui-skin-center`; the install path (`dsh plugin --profile <name> add` and the `$DSH_HOME/skins/<id>` directory layout); the npm `files` whitelist, which still ships only `blue-fantasy` while the new skin is market content installed on demand into `$DSH_HOME/skins/<id>/`; the `dsh.engines.dsh` floor and the `@deepseek-ai/dsh` peer floor, both still `>=0.2.2-rc.1` (this repository did not follow the main repository's rc.2 raise in this release); the persisted file name and keys of the v2 active-state document; the semantic attribute names such as `data-dsh-skin` and `data-dsh-part`; and the wire fields. The new skin is a pure CSS asset (`hooks` is empty, nothing in it executes) and introduces no runtime contract, while the `remiel-starlit` repair touches only its own token values and manifest version, leaving the Reviewed Skin Hooks record as it was.

### New Features

- The `whale-watercolour` skin arrives (188c0af, #77, skin 1.0.2, order 54, primary `#1B5D9A`): a light-only skin on one watercolour illustration - a blue-haired girl with white roses and a silver pendant chain in her hair, emerald eyes - where the chrome is not drawn on the picture but is a translucent cream veil, so the picture shows through from behind the paper. Every palette entry is measured out of that picture rather than chosen by eye: cream `#FAF9F5` is the area covering 34.6% of it, ink `#0D2045` is the mean of its darkest 0.2% pressed one step deeper, sky `#1B5D9A` the mean of its most saturated 2% pressed one step deeper, and jade `#186654` comes from the measured eye green pressed one step deeper at the same hue; ice blue `#B0C8D8` is decoration only, because over any of these veils it measures 1.65-2.18:1 and can never be an interactive boundary (3:1), where sky and jade are used instead. The five veil alphas are reverse-solved in sRGB (gamma-encoded) space rather than linear light: `rgba(250,249,245,0.678)` over `rgb(38,60,100)` lands on `rgb(182,188,198)`, which the sRGB model hits channel by channel while the linear-light one is off by 29
- The veil thickness is re-solved on per-cell paper evidence instead of "the darkest 1%", which reads the text itself and the dark mass of her hair as paper: 14x48 px cells take the p75-luminance pixel as paper and fold back through `under = (P - a*VEIL)/(1-a)`, so any candidate alpha can be re-composited and checked per sample. All five knobs move at once - sidebar/masthead 0.82 to 0.56, header 0.78 to 0.56, composer 0.66 to 0.52, conversation sheet 0.58 to 0.46 and then 0.38, menus 0.95 to 0.80 - taking picture retention from 18% / 22% / 34% / 42% / 5% to 44% / 44% / 48% / more / 20% (the sheet gets its own third pass to 0.38, with a per-cell floor of 0.34 and the worst 5% of text cells still at 7.2:1); no text colour changed, the worst 5% of text cells still measure 9.14 / 8.18 / 8.16 / 10.67 against a 7.0 floor, and every secondary and state tier stays at 5.6:1 or better. Menus have no live-shell sample (they have to be opened), so they keep a 0.15 margin
- The dark half is pinned to the light half rather than merely declared equal: on the running shell four things still produced a second set of values - 5 engine `--sk-*` tokens, 22 shell tokens this skin never remapped (deep-diving / shimmer, menu icon, link, file diff and code diff, menu and turn-trigger surfaces, onboarding, and the 9 shiki syntax colours), two dark rules that are not tokens at all (the tool-icon tile fill and the right-pane guide glyph colour), and `color-scheme`, which turns every author-unstyled native control white. All of them now resolve to the light values: **0 of 553 shell custom properties differ between the two themes, 0 computed-style differences appear across 8 live scenes**, and on the official market try-on page the light and dark renders are **byte-identical, 0 of 1,680,000 pixels**. The light side is untouched: 36 of 36 pinned values still resolve to exactly what they resolved to before

### Bug Fixes

- `remiel-starlit` read contrast in dark and light (d53865e, #105): the dark branch inverted the whole `--dsw-static-neutral-*` ramp to light values, so every white-on-dark assumption the official shell holds broke at once - the deliverables, plan, schedule, forge and changed-files cards take their plate fill from `--dsw-static-neutral-850` while `--dsw-alias-label-primary` stayed light, leaving white text on a `#ded7db` plate at **1.28:1**. That ramp is a theme-independent absolute palette in the official theme and only `--dsw-alias-*` flips between themes, so inverting it puts any static-backed surface outside the theme system with nothing to catch it. The repair keeps the ramp dark in the dark branch instead of mirroring it, and keeps `--dsw-static-neutral-00` white because the shell uses it as a white overlay (icon plates at 50 percent, elevation glow, the sidebar flash highlight), where flipping it would turn every lift into a darken
- The same pass raises the light translucent surface alpha (`bg-base` 0.42 to 0.62, `sidebar-fill` 0.60 to 0.74, plus layer-1..3, bubble and input) so tertiary and caption text survives the darker regions of the calm backdrop, deepens `label-tertiary` / `caption` / `dimmed` to reach 4.5:1 on those surfaces, and declares two tokens the skin never remapped and that therefore fell back to the official palette - `--dsw-alias-link` resolved to a washed-out pink at 1.97:1 (every Markdown link and WebBlock reference) and `--dsw-alias-toast-label` kept the shell value on the skin's own toast surface. Measured on the rebuilt tokens: dark cards 1.28:1 to 11.07:1, light cards 10.82:1, note text 7.44:1, and **all 192 surface/text/theme/backdrop combinations pass WCAG AA 4.5:1**
- The skin version moves from 0.1.0 to 0.1.1 and the published artwork is documented: the store compares the manifest version, so an unchanged one would make this repair invisible as an update and users would never receive it; `NOTICE` states that the assets carry the official Zenless Zone Zero logo watermark as published, that the mark belongs to miHoYo and is part of the material, and that the skin neither crops nor covers it, keeping the required copyright mark intact; both READMEs gain a 0.1.1 change note and the evidence screenshots are re-rendered from the rebuilt stylesheet
