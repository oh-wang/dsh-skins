皮肤中心发布 0.4.18，与 dsh-web 全家桶 0.4.18 同版本发布。本版本没有用户可见的功能变更：它把整套 `@deepseek-ai` SDK 队列从 `0.2.2-rc.1` 对齐到 `0.2.2-rc.2`，宿主下限随之抬到 `>=0.2.2-rc.2`。皮肤目录仍是 66 套，皮肤资产、契约文档、Reviewed Skin Hooks 记录与 npm `files` 白名单一个不动。

> **兼容性**：本版本有一处收紧需要先看：`dsh.engines.dsh` 与 `@deepseek-ai/dsh` 对等依赖的下限从 `>=0.2.2-rc.1` 提到 `>=0.2.2-rc.2`，低于该版本的宿主装不上 0.4.18，要先把宿主升到 `0.2.2-rc.2` 或更高。除此之外没有破坏性变更，没有需要手工迁移的改动：包名 `@linxin666/dsh-client-ui-skin-center`；安装方式（`dsh plugin --profile <name> add` 与 `$DSH_HOME/skins/<id>` 目录布局）；npm `files` 白名单仍只内置 `blue-fantasy`；v2 活跃状态文档的持久化文件名与键名；`data-dsh-skin`、`data-dsh-part` 等语义属性名；线协议字段——全部未改名。运行时代码与皮肤资产都不动，`lib/` 重建后逐字节相同。

### 升级提示

- 宿主需要 `0.2.2-rc.2` 或更高。npm 上 `@deepseek-ai/dsh` 的 `latest` 标签此刻仍指向 `0.2.2-rc.1`，照 `latest` 装宿主会停在旧队列上，装宿主请指向 `next` 标签：`npm i -g @deepseek-ai/dsh@next`。

### 其他改动

- SDK 队列对齐到 `0.2.2-rc.2`（43f4bfa）：九个 `@deepseek-ai` 开发依赖从 `0.2.2-rc.1` 改成 `0.2.2-rc.2`，`dsh.engines.dsh` 与 `@deepseek-ai/dsh` 对等依赖同步抬到 `>=0.2.2-rc.2`；`@deepseek-ai/cordis`（`^4.1.0`）与 `@deepseek-ai/schemastery`（`^3.19.0`）不动，因为 rc.2 没有移动它们
- 发布年龄豁免账本与 lockfile 跟着队列一起走（43f4bfa）：`pnpm-workspace.yaml` 里 321 条写死 `0.2.2-rc.1` 的 `minimumReleaseAgeExclude` 条目全部改到 rc.2——真正决定安装解析到哪套队列的是这本账，只改清单会在声明 rc.2 的同时装到 rc.1；pnpm 另追加新解析触达的 14 个传递依赖，`pnpm-lock.yaml` 一并重生成
- 没有源码适配（43f4bfa）：rc.2 收回 `@deepseek-ai/dsh-subagent/internal` 这类内部子路径导出，并重做 `startActivation`、`drainChildren` 与 `drainDescendants`，本仓一个都不引用；它实际消费的 `cordis`、`schemastery`、`dsh-host-webserver`、`dsh-client-ui-slots`、`-settings`、`-theme`、`-renderer`、`dsh-api-remotes`、`dsh-api-workspace-controller`、`dsh-client-locale` 与 `dsh-settings` 保持源码用到的形状，`lib/` 重建后逐字节相同
- 两份冻结契约复核过而不是假定（43f4bfa）：五个 `dsh.client.inject` 包在 rc.2 下仍各自发布 `./client` 入口；`contracts/official-tokens-v1.json` 对照 rc.2 主题库，rc.2 没有收回它记录的任何一条令牌，335 条快照仍是 rc.2 主题面的合法子集
- README 两语的宿主下限徽章改到 `>=0.2.2-rc.2`，`README.i18n.yaml` 重新记录配对哈希（43f4bfa）
- 版本对齐：`package.json` 的 `version` 对齐到 `0.4.18`，与 dsh-web 全家桶 0.4.18 同版本发布；本仓只发一个包，`package.json` 的 `version` 是唯一的版本声明
- 目录规模：仓库内目录皮肤 66 套，npm 白名单仍只内置 `blue-fantasy`，其余全部作为市场内容按需安装；本版不新增皮肤，也不改任何皮肤的 manifest 与令牌

The skin center publishes 0.4.18, on the same version as the dsh-web family's 0.4.18. This release carries no user-visible feature change: it aligns the whole `@deepseek-ai` SDK cohort from `0.2.2-rc.1` to `0.2.2-rc.2` and raises the host floor with it to `>=0.2.2-rc.2`. The catalog stays at 66 skins, and the skin assets, the contract documents, the Reviewed Skin Hooks record and the npm `files` whitelist do not move.

> **Compatibility**: one tightening has to be read first: the `dsh.engines.dsh` floor and the `@deepseek-ai/dsh` peer floor move from `>=0.2.2-rc.1` to `>=0.2.2-rc.2`, so a host below that version cannot install 0.4.18 and has to be raised to `0.2.2-rc.2` or later first. Beyond that this is not a breaking change and nothing has to be migrated by hand: the package name `@linxin666/dsh-client-ui-skin-center`; the install path (`dsh plugin --profile <name> add` and the `$DSH_HOME/skins/<id>` directory layout); the npm `files` whitelist, which still ships only `blue-fantasy`; the persisted file name and keys of the v2 active-state document; the semantic attribute names such as `data-dsh-skin` and `data-dsh-part`; and the wire fields. Neither runtime code nor skin assets move, and `lib/` rebuilds byte-identical.

### Upgrading

- The host must be `0.2.2-rc.2` or later. The `latest` tag of `@deepseek-ai/dsh` on npm still points at `0.2.2-rc.1` at this moment, so installing the host from `latest` stops on the old cohort; point at the `next` tag instead: `npm i -g @deepseek-ai/dsh@next`.

### Other Changes

- SDK cohort aligned to `0.2.2-rc.2` (43f4bfa): all nine `@deepseek-ai` development dependencies move from `0.2.2-rc.1` to `0.2.2-rc.2`, and the `dsh.engines.dsh` floor and the `@deepseek-ai/dsh` peer floor move to `>=0.2.2-rc.2` with them; `@deepseek-ai/cordis` (`^4.1.0`) and `@deepseek-ai/schemastery` (`^3.19.0`) stay put because rc.2 does not move them
- The release-age ledger and the lockfile travel with the cohort (43f4bfa): all 321 `minimumReleaseAgeExclude` entries that pinned `0.2.2-rc.1` in `pnpm-workspace.yaml` move to rc.2 - that ledger is what actually decides which cohort the install resolves, so moving the manifests alone would declare rc.2 while installing rc.1; pnpm also appends the 14 transitives the new resolution reaches, and `pnpm-lock.yaml` is regenerated
- No source adaptation (43f4bfa): rc.2 withdraws internal subpath exports such as `@deepseek-ai/dsh-subagent/internal` and reshapes `startActivation`, `drainChildren` and `drainDescendants`, none of which this repository imports; the surfaces it does consume - `cordis`, `schemastery`, `dsh-host-webserver`, `dsh-client-ui-slots`, `-settings`, `-theme`, `-renderer`, `dsh-api-remotes`, `dsh-api-workspace-controller`, `dsh-client-locale` and `dsh-settings` - keep every shape the sources use, so `lib/` rebuilds byte-identical
- Two frozen contracts were re-verified rather than assumed (43f4bfa): all five `dsh.client.inject` packages still publish a `./client` entry under rc.2, and `contracts/official-tokens-v1.json` compared against the rc.2 theme library shows rc.2 retiring no token the snapshot records, so its 335 entries stay a valid subset of the rc.2 theme surface
- The host-floor badge on both sides of the README moves to `>=0.2.2-rc.2` and `README.i18n.yaml` re-records the pairing hashes (43f4bfa)
- Version alignment: `version` in `package.json` aligns to `0.4.18` on the same version as the dsh-web family's 0.4.18; this repository publishes one package, so that field is the only version declaration in it
- Catalog size: 66 catalog skins in the repository, while the npm whitelist still ships `blue-fantasy` only and every other skin is market content installed on demand; this release adds no skin and changes no skin's manifest or tokens
